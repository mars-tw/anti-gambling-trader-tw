# 2026-10-07 深度稽核與修正

稽核基準為主分支 `9d938b6`。本輪以合成交易、離線測試與模擬券商重現問題，再由不同執行者複核修正。未連接真實交易帳戶，未送出或取消真實訂單。

## 已修正的問題

- **虧損資料被忽略**：JSON 現在讀取所有列的欄位，支援明確的括號負數及 USDT／USDC 金額；自動欄位對應遇到多個金融欄位別名時拒絕猜測，要求統一欄名或明示對應。
- **不完整資料取得正面裁決**：拒絕列與疑似精確重複交易有結構化計數。分析、篩選、排序與樣本外檢查保留完整性限制；原地新增交易後也會重新檢查。問題未釐清前不認證正向優勢，HTML 與分享卡同步揭露。
- **非法數值通過檢定**：統計入口拒絕 NaN、無限大、布林值、無效參數與數值溢位；老師宣稱檢查不再把打平說成負報酬，也不把內部樣本數哨兵當作建議。
- **紙上交易憑空獲利或污染資產**：不具立即成交條件的限價單拒單；成交必須符合現價。數量、報價、費率、滑價與結算運算受到檢查，涵蓋微量裸賣、下溢及加權成本溢位。
- **真實交易閘門不夠嚴格**：只有布林值 `True` 能確認解鎖；Alpaca／Tradier 撤單也先檢查閘門。以 Mock 驗證未解鎖時沒有外部呼叫。
- **檔案覆寫**：CLI 拒絕輸入／輸出別名、硬連結與重複輸出；scaffold 保護既有專案、限制生成路徑，並以 exclusive create 防止檢查後才出現的檔案被覆寫。
- **文件與開發流程**：修正 p 值、bootstrap 假設、模擬解析度／誤差與回溯驗證的敘述；區分本機 CLI、雲端 AI、CDN 與券商 API 的資料流。兩份技能同步，補齊開發依賴與跨平台 CI。
- **Windows 獨立程式編碼**：遠端 CI 重現生成程式在 CP1252 終端機因中文輸出崩潰；生成程式現在於執行時設定 UTF-8 輸出，保留匯入時的串流設定。

## 已完成的驗證

- Windows／Python 3.13 全套：**495 passed，1 skipped**。跳過的是本機無法建立符號連結的案例；硬連結與路徑別名已實測。
- 9 個獨立攻擊性輸入重現案例通過；另驗證可變 TradeLog 的重複交易限制會傳給篩選結果。
- 從 wheel 安裝到全新環境，在原始碼目錄之外成功執行 `start`、`demo`、分析輸出與 scaffold；生成的預設紙上交易專案可執行並產生圖表。
- 生成程式在 `PYTHONUTF8=0` 搭配 ASCII、CP1252、CP950 的 subprocess 測試均通過；新 wheel 的完整執行流程也在強制 ASCII 輸出環境驗證。
- 瀏覽器實際檢查 HTML／分享卡：缺漏資料即使顯示高勝率，仍明示完整性未通過與判讀限制。
- 固定 seed 的既有 bootstrap 校準實驗維持原結果：400 次零期望常態實驗，bootstrap 型一誤差 5.5%，t 檢定 5.2%；這項小型實驗不代表所有損益分布都已校準。

CI 定義在 [ci.yml](../.github/workflows/ci.yml)，涵蓋 Ubuntu／Windows 與 Python 3.10／3.13，以及移出原始碼目錄後的 wheel／紙上專案驗收。實際遠端執行結果以 GitHub Actions 為準。

## 驗證界線

這些結果不表示真實券商 SDK、認證、即時行情或實盤交易已驗證；也不證明任何策略未來有獲利能力。精確重複列只表示需要核對，不等於認定造假；相同金額但缺乏時間資料的交易不會僅因此被當成重複。
